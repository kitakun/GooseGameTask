# GooseGameTask

Браузерная игра, где игроки соревнуются, кто быстрее и больше натапает по виртуальному гусю, подхватившему мутацию G-42.

## 🚀 Быстрый старт

### Быстрый запуск для тестирования

1. **Клонируйте репозиторий:**
```bash
git clone <repository-url>
cd GooseGameTask
```

2. **Установите зависимости:**
```bash
# Установка всех зависимостей
npm install

# Установка зависимостей бекенда
cd backend && npm install

# Установка зависимостей фронтенда
cd ../frontend && npm install
```

3. **Настройте базу данных (PostgreSQL):**
```bash
cd ../backend

# Создайте .env файл
cp env.example .env

# Отредактируйте .env для использования PostgreSQL
echo 'DATABASE_URL="postgresql://username:password@localhost:5433/goosegame"' > .env
echo 'JWT_SECRET="test-secret-key"' >> .env
echo 'PORT=3001' >> .env
```

4. **Инициализируйте базу данных:**
```bash
# Генерируйте Prisma клиент
npm run db:generate

# Примените миграции к базе данных
npm run db:migrate

# Инициализируйте базу данных
npm run db:init
```

5. **Запустите приложение:**
```bash
# Из корневой директории
npm run dev
```

6. **Откройте в браузере:**
- Фронтенд: http://localhost:5173
- Бекенд API: http://localhost:3001

### Тестовые пользователи
- **Админ**: `admin` / любой пароль (роль: ADMIN)
- **Никита**: `nikita` / любой пароль (роль: NIKITA)
- **Игрок**: любое другое имя / любой пароль (роль: SURVIVOR)

## 🎮 Правила игры

### Система очков
- **1 тап = 1 очко**
- **Каждый 11-й тап = 10 очков**
- Тапы засчитываются только во время активного раунда
- Активный раунд = начался, но еще не закончился

### Управление раундами
- Админ может создавать новые раунды
- Раунды автоматически заканчиваются по истечении времени
- После окончания раунда определяется победитель
- Статистика обновляется каждые 2 секунды

## 🛠️ Технологии

### Backend
- **Node.js + TypeScript** - Основная платформа
- **Fastify** - Высокопроизводительный веб-фреймворк
- **Prisma** - Современный ORM для работы с базой данных
- **PostgreSQL** - Надежная реляционная база данных
- **JWT** - Аутентификация и авторизация
- **Event Sourcing** - Архитектурный паттерн для хранения событий
- **EventStore** - Хранилище событий в памяти

### Frontend
- **React + TypeScript** - Пользовательский интерфейс
- **Vite** - Быстрый сборщик и dev-сервер
- **React Router** - Клиентская маршрутизация
- **Zustand** - Легковесное управление состоянием
- **Tailwind CSS** - Utility-first CSS фреймворк
- **Lucide React** - Современные иконки

## 🏗️ Архитектура

### Backend Architecture

#### Event Sourcing Pattern
Бекенд использует архитектурный паттерн Event Sourcing для обеспечения консистентности данных:

```
backend/src/
├── app/                    # Слой приложения
│   ├── index.ts           # Инициализация сервера
│   ├── plugins.ts         # Регистрация плагинов
│   ├── middleware.ts      # Регистрация middleware
│   ├── routes.ts          # Регистрация роутов
│   ├── providers.ts       # Провайдеры (Prisma, etc.)
│   └── eventStore.ts      # Конфигурация EventStore
├── entities/              # Доменные сущности
│   ├── events/            # События и Event Store
│   │   ├── eventStore.ts  # Сервис Event Store
│   │   ├── snapshotService.ts # Сервис снимков
│   │   ├── types.ts       # Типы событий
│   │   └── constants.ts   # Константы событий
│   ├── round/             # Агрегат раунда
│   │   └── roundAggregate.ts # Бизнес-логика раунда
│   └── userTap/           # Агрегат тапов пользователя
│       └── userTapAggregate.ts # Бизнес-логика тапов
├── pages/                 # Слой страниц (контроллеры)
│   ├── auth/              # Аутентификация
│   │   └── authController.ts
│   ├── rounds/            # Раунды
│   │   ├── eventSourcedApi.ts # Event Sourced API
│   │   └── adminController.ts # Админ контроллеры
│   └── tap/               # Тапы
│       └── tapController.ts
├── shared/                # Общий слой
│   ├── api/               # API типы и утилиты
│   ├── config/            # Конфигурация
│   ├── lib/               # Общие библиотеки
│   │   ├── repositories/  # Репозитории
│   │   ├── jobs/          # Фоновые задачи
│   │   ├── cache/         # Кэш сервисы
│   │   ├── locks/         # Сервисы блокировок
│   │   └── utils/         # Утилиты
│   └── types/             # Общие типы
└── scripts/               # Скрипты
    └── init-db.js         # Инициализация БД
```

#### Ключевые принципы архитектуры:
- **Event Sourcing**: Все изменения сохраняются как события
- **CQRS**: Разделение команд и запросов
- **Агрегаты**: Инкапсуляция бизнес-логики
- **Снимки**: Оптимизация производительности
- **Типобезопасность**: Строгая типизация на всех уровнях

### Frontend Architecture

#### Component-Based Architecture
Фронтенд построен на основе компонентной архитектуры с использованием современных React паттернов:

```
frontend/src/
├── components/             # Переиспользуемые компоненты
│   ├── Header.tsx         # Шапка приложения
│   ├── Layout.tsx         # Основной лейаут
│   ├── LoadingSpinner.tsx # Компонент загрузки
│   └── RoundPage/         # Компоненты страницы раунда
│       ├── GameArea.tsx   # Игровая область
│       ├── RoundHeader.tsx# Заголовок раунда
│       ├── RoundStatusCard.tsx # Статус раунда
│       ├── StatsSection.tsx    # Статистика
│       └── TapResult.tsx       # Результат тапа
├── pages/                  # Страницы приложения
│   ├── LoginPage.tsx      # Страница входа
│   ├── RoundsPage.tsx     # Список раундов
│   └── RoundPage.tsx      # Страница раунда
├── store/                  # Управление состоянием (Zustand)
│   ├── authStore.ts       # Состояние аутентификации
│   └── roundsStore.ts     # Состояние раундов
├── api/                    # API клиент
│   ├── client.ts          # Базовый клиент
│   ├── client.auth.ts     # API аутентификации
│   ├── client.rounds.ts   # API раундов
│   └── client.tap.ts      # API тапов
├── hooks/                  # Кастомные хуки
│   └── useDelayedLoader.ts# Хук для отложенной загрузки
├── utils/                  # Утилиты
│   └── roundUtils.ts      # Утилиты для работы с раундами
└── types/                  # TypeScript типы
    └── index.ts           # Общие типы
```

#### Ключевые особенности фронтенда:
- **Оптимизация производительности**: React.memo, useCallback, delayed loader
- **Типобезопасность**: Строгая типизация с TypeScript
- **Состояние**: Zustand для простого и эффективного управления состоянием
- **Стили**: Tailwind CSS для быстрой разработки UI
- **Роутинг**: React Router для SPA навигации
- **Автообновление**: Статистика обновляется каждые 2 секунды

### Масштабируемость
Приложение разработано с учетом возможности запуска нескольких инстансов бекенда:
- **Статeless архитектура**: Нет привязки пользователя к определенному инстансу
- **Event Sourcing**: Обеспечивает консистентность данных между инстансами
- **In-memory сервисы**: Lock и cache сервисы работают в памяти каждого инстанса
- **Общая база данных**: Все инстансы используют одну PostgreSQL базу
- **Порт-конфигурация**: Каждый инстанс может работать на своем порту

### Безопасность
- **JWT токены** для аутентификации
- **Хеширование паролей** с bcrypt
- **Валидация входных данных** с Zod
- **Проверка ролей** и прав доступа
- **CORS настройки** для безопасности API
